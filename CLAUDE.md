# CLAUDE.md

Context for Claude working in this repo.

## What this is

A personal Catan clone with expansion support, hosted on GitHub Pages, played privately with friends. Built because colonist.io paywalls the expansions.

## Tech stack (locked)

TypeScript, Vite, React, hand-rolled SVG for the board, `honeycomb-grid` for hex math, Trystero for WebRTC peer-to-peer multiplayer, Zustand for state, Vitest for tests. No backend — GitHub Pages is static-only.

## Architecture

Five layers, separated by directory:

- **`src/game/`** — pure TypeScript game logic. No React, no DOM, no network imports. All state mutations go through `applyAction(state, action) => state`. Deterministic. Unit-tested.
- **`src/ai/`** — pure heuristic AI. Exports `chooseAction(state, playerId) => Action | null`, `shouldAcceptTrade`, `tryCounterTrade`. No React or store imports — same purity contract as `src/game/`. `src/ai/nn/` holds the trained-network AI for the base game (see "Learned agent").
- **`src/net/`** — Trystero (Nostr relays) wrapper. Typed channels for hello/lobby/start/action/snapshot/chat, persistent UUID via localStorage, short room codes. Consumed only by `networkStore`, except `diagnostics.ts` (the Network test screen and the join-failure report also read it).
- **`src/ui/`** — React components + SVG board. Reads state from `src/store`, dispatches actions via the store, hosts the `AIDriver` component that runs AI moves.
- **`src/rulebook/`** — self-contained rulebook (TSX topics + inline SVG diagrams), rendered either as a full screen from the main menu or inside an overlay via the in-game `?` button.

Three Zustand stores under `src/store/`:
- `gameStore` — `GameState` + UI mode + dialogs + pendingRobberHex + handoffPending + `lastActionSnapshot` (game+logStore pair captured for the last reversible action). Exposes `dispatch(action)` (broadcasts) and `applyLocal(action)` (silent, used by network receivers). `undo()` restores both `game` and `logStore` from the snapshot; solo/hot-seat only, fires only on the last `buildRoad` / `buildSettlement` / `buildCity` / `buyDevCard` / `bankTrade`.
- `networkStore` — connection state, role (solo/host/guest/spectator), lobby, chat, online peer tracking. Registers with `gameStore` via `registerBroadcastHandler` to avoid circular imports.
- `logStore` — game-event log + per-step timeline snapshots (per-player VP / handTotal / gainedTotal / gainedByResource / knightsPlayed / longestRoadLength / tradesCount / tradesGiven / tradesReceived, plus `turnNumber`), match stats (roll counts + resourcesInCirculation), and the full `actions: Action[]` + initial `GameState` so the end-game replay can rebuild any historical step. Populated as a side effect of every successful `dispatch`/`applyLocal`. Exposes `snapshot()`/`restore()` so `gameStore.undo()` can keep the two stores in sync. Lives outside `GameState` so the engine stays deterministic; each peer derives its own log from the actions it sees, so multiplayer needs no extra wire traffic. Turn numbering is revolution-based: a turn ticks over only when the table cycles back to the first player in `playerOrder`. For 5+ players the paired-player rule means two seats act per paired turn, but only the second `endTurn` advances `turnHolderIndex`, so the counter still ticks once per paired turn rather than per acting seat.

## Expansion model

Each rule set lives as a self-contained module in `src/game/modules/`: base game, Seafarers, Cities & Knights, Traders & Barbarians, Explorers & Pirates. Modules contribute action handlers, initial-state extensions, and (optionally) board generation. The engine composes the active modules at game start.

**No `if (expansion === 'cities')` conditionals scattered through the code.** If you find yourself wanting one, add a module hook instead.

## Board scenario system

Modular layout types live in `src/game/board/scenarioTypes.ts` (`ScenarioPosition`, `ScenarioPortAnchor`, `ScenarioPools`, `ScenarioLayout`), shared materializer in `src/game/board/layoutMaterializer.ts`, and assembly helper in `src/game/board/scenarioAssembly.ts`. Both Seafarers and base-game scenarios feed through these.

- **Base scenarios** (`src/game/modules/base/scenarios/`): the colonist.io-style Fun Maps. `BaseScenario` records each declare optional `layout3p` / `layout4p` / `layout5_6p` plus optional volcano metadata. `Standard` is the sentinel — no layout, falls through to the legacy hardcoded `generateBoard()` so the default new-game flow is bit-for-bit unchanged.
- **Seafarers scenarios** (`src/game/modules/seafarers/board/scenarios/`): the 9 official scenarios. Same modular layout machinery + Seafarers-specific fields (`fogHexes`, scenario flags, and per-board-size `extras3_4` / `extras5_6` mechanic data — see "Seafarers scenario mechanics").
- **createGame routing**: if Seafarers is on → `generateSeafarersBoard`; else if `baseScenarioId !== 'standard'` → `generateBaseScenarioBoard`; else → legacy `generateBoard`.

`ScenarioPosition` extensions: `fixedTerrain` pins terrain (Black Forest's fixed wood); `forceToken` joins a desert position to the token pool (Volcano's desert-with-a-number); `fixedToken` pins an exact number on a position (Volcano pinned to 6). `ScenarioLayout.tokenConstraints.allow6_8Adjacent` relaxes the no-adjacent-reds retry (Black Forest).

## Base-game Fun Maps

The colonist.io-style maps live as `BaseScenario` entries; pick from the **Base map** dropdown on the New Game screen.

- **Gold Rush** — 2 gold fields (3 at 5-6p) mixed into the terrain pool. Uses the existing Seafarers-engine gold flow (settlement adjacent to gold = pick any resource on production).
- **Volcano** — center hex is a fixed desert with a pinned 6 token. Setup blocks placement on volcano-adjacent vertices. When the volcano's number rolls, `maybeEruptVolcano` in `src/game/actions/dice.ts` picks a random occupied adjacent corner using seeded `state.rngState` and destroys/downgrades the building inline (no separate action — peers reduce identically). Log entry: `volcanoEruption` with 🌋 prefix, derived in `logStore.record` by diffing settlement/city counts on volcano corners. AI gets a `-3.5` penalty for volcano-adjacent vertices in `vertexScore`. UI: `src/ui/game/base/VolcanoMarker.tsx`.
- **Black Forest** — 5 fixed-wood interior hexes; `tokenConstraints.allow6_8Adjacent: true` so a dense red cluster can land anywhere.
- **Diamond / Gear / Lakes / Pond / Twirl** — pure shape variants (16-hex rhombus, 13-hex gear, 3 interior lakes, 1 center sea, 21-hex spiral). No new mechanics — the engine handles interior sea hexes for free (the distance rule across narrow lakes already works via the hex graph adjacency).

Seafarers wrapper pattern: `src/game/modules/seafarers/actions/` wraps the base `buildSettlement` / `placeInitialSettlement` / `buildRoad` / `placeInitialRoad` / `playRoadBuilding` / `rollDice` / `playKnight` / `endTurn` handlers. Every placement path then runs the shared hooks in `seafarers/hooks.ts` (`afterShipPlaced` / `afterRoadPlaced` / `afterSettlementPlaced`): fog discovery, Forgotten Tribe pickups, Cloth trade routes, tribe-port placement, island bonus / home islands. `buildShip`, `moveShip`, `placeInitialShip`, `chooseGoldResource`, robber/pirate choice, `movePirate`, `claimWonder` / `buildWonder`, `placeTribePort` and `stealResource` are Seafarers-native. The module also provides two `RuleModule` hooks used by the engine: `routeLength` (Longest Route = roads + ships, joined only at your buildings; read it via `calculateRouteLength` in `engine.ts`, never `calculateLongestRoad`, anywhere a route length is shown) and `hasWon` (scenario win conditions).

General rules (2025 rulebook, all in the engine): ships connect only to your ships or buildings (never roads); ships may sail along the sea frame (single-hex edges); no ships on, to or from the pirate's hex edges; one ship move per turn, not a ship built this turn (`player.builtShipsThisTurn`), needs an open end (roads don't close an end); a coastal starting settlement may take a ship instead of a road (`placeInitialShip`); Road Building places roads and/or ships (`edges` + `ships`); the robber goes only on land on the table (`canMoveRobberTo`: no sea, no fog, no `robberBlockedHexes`); gold picks are capped by the bank (`requiredGoldPicks`).

## Seafarers scenario mechanics

Each official scenario follows its 2025 rulebook text. Scenario records (`src/game/modules/seafarers/board/types.ts`) carry flags (`startingPlacementZone`, `bonusOnEveryIsland`, `noPirate`, `noLongestRoad`, `noLargestArmy`, `setupRounds`, `numberedHexesOnly`) plus map-specific data in `extras3_4` / `extras5_6` (axial `VertexRef` / `EdgeRef`s resolved by the generator). Forgotten Tribe, Cloth for Catan, Pirate Islands and Wonders of Catan are **fixed setups transcribed from the rulebook maps** (`fixedPositions`, `noToken` for unnumbered land); their terrain / number counts match the component tables exactly. VP targets are the rulebook's (5-6p uses the same target).

- **Island bonus** (Heading for New Shores, Four Islands, Through the Desert: 2 VP; Wonders, New World: 1 VP) — `state.islandChips[]` = `{ islandId, vp, claimedBy[], homeOf[] }` (`seafarers/islandBonus.ts`). *Every* player earns each island's bonus once, on their first settlement there. Starting settlements mark home islands (no bonus). `bonusOnEveryIsland` (Four Islands, New World) gives the largest island a bonus too. `state.startingIslands` restricts setup.
- **Fog Islands** — no island bonus. `revealFogAroundEdge` discovers every hex around both ends of a placed road/ship (settlements don't reveal). Unexplored fog doesn't produce, pays no setup resources, can't hold the robber or a ship edge.
- **Through the Desert** — `desertIsBoundary` makes the far strip its own region.
- **Forgotten Tribe** (`seafarers/tribe.ts`) — `state.tribeTokens[]` sit on edges (8/10 VP tokens, 4/6 face-down dev cards drawn from the deck at setup, 6/8 ports). A ship built or moved onto the edge takes it: `player.tribeVp`, a dev card into `boughtThisTurn` (VP card counts at once), or a port into `player.heldPorts`, placed via the `placeTribePort` phase next to a coastal settlement (frame edges count; one edge from other ports) as soon as possible. `settlementBlockedHexes` / `robberBlockedHexes` = unnumbered land. No island bonus.
- **Cloth for Catan** (`seafarers/cloth.ts`) — `state.clothVillages[]` (vertex, number, 5 cloth, partners) + `state.clothSupply` (10). A route (roads/ships joined at own buildings) from a building to a village opens trade (+1 cloth); its number pays each partner 1 (topped up from the supply; an empty village stops). Village corners count as anchors for `isShipMovable` (closed routes). 3 setup rounds (`settings.setupRounds`, `setupRound3`; only the third pays). No Longest Route; small islands blocked for settlements and the robber; the pirate only after your first trade route, stealing a card or cloth (`stealCloth`). The `endTurn` wrapper ends the game when 5+ villages are empty (most VP, then most cloth).
- **Pirate Islands** (`seafarers/pirateIslands.ts`) — `state.pirateIslands` = `{ mainIsland, path, fleetIndex, noAttackHex?, fortresses[], lastFleetAttack?, lastFortressAttack? }`; `board.pirateHex` is the fleet. Each player starts with a slot's settlement + ship (`player.warships[]` ⊆ `ships`). The `rollDice` wrapper moves the fleet by the lower die and attacks buildings on its hex (lose: discard 1 + 1 per city there; win: a resource of choice via `chooseGoldResource`, before "Resolve a 7" via `afterPicks: 'resolveSeven'`). No robber (`robberActive: false`); a 7 goes to the `stealResource` phase. `pirateIslandsShipViolation` enforces one non-branching shortest-path line from the main island to the beachhead then the fortress; `pirateIslandsSettlementAllowed` allows only your beachhead off the main island and treats fortresses as buildings. Knights (VP cards at 4+p) convert the ship nearest the route start into a warship. The `endTurn` wrapper resolves the fortress assault with seeded RNG (3 wins recapture → it becomes a settlement); the win needs the recaptured fortress AND the VP target. No Longest Route / Largest Army.
- **Wonders of Catan** (`seafarers/wonders/catalogue.ts`) — the 5 rulebook wonders (+ Lighthouse and Great Library at 5-6p) with their tile costs and requirements; `state.wonderSites` holds the Great Wall / Great Bridge / lighthouse marker vertices, `state.setupBlockedVertices` the markers + "X" markers. `claimWonder` (one per player) then `buildWonder` per level; levels give no VP. Level 4 wins at once; otherwise the target VP plus a strictly higher level than everyone (`wonderLevelLead`). No pirate.
- **New World** — +1 VP island bonus, start anywhere. The shipped maps are fixed approximations (the rulebook randomizes the land each game; follow-up).

The "… 2" scenarios are alternate maps of the first four, sharing their rules.

## Scenario tracker UI

`src/ui/panels/ScenarioPanel.tsx` renders the active scenario: its win condition, per-player island bonuses, fog progress, cloth (per player + villages emptied), Pirate Islands fortresses / warships / last attacks, wonders and the tribe's remaining gifts. `hasScenarioTracker(game)` decides whether `SidePanelTabs` shows the "Scenario" tab. Board markers live in `src/ui/game/seafarers/ScenarioMarkers.tsx` (tribe pickups, villages, wonder sites + X markers, the fleet loop, fortresses, beachheads; pointer events off, drawn under the overlay), plus `PirateMarker` and `Ship` (warships drawn with a red sail). `HexTile` accepts a `foggy` prop. Seafarers log lines come from `src/store/seafarersLog.ts` (diff-based, so effects inside other actions are logged). Online, every dialog that dispatches for a seat is gated with `useCanAct` (`src/ui/shared/useCanAct.ts`) so only that seat's device gets live buttons.

For Traders & Barbarians the same panel renders a separate Traders block; Rivers of Catan (gold, Wealthiest / Poor, bridges per player) and Fishing on Catan (tokens per player, supply / discards, the boot, where the robber is, spend costs) come from `src/ui/panels/traders/RiversFishingTrackers.tsx`, plus the Strongest Ports holder when that variant is on. `HandPanel` shows the device's coins / fish tokens / boot in `TradersHandStrip`; `OpponentPanel` shows gold, the wealth tiles, fish counts and the boot. The icons (coin, money bags, fish tokens, boot) are SVG in `src/ui/game/traders/TradersIcons.tsx`; board art is `TradersBoardLayer` (rivers, bridge sites, fishing-ground chevrons), `Bridge`, and the lake tile (`LakeArt`, drawn by `HexTexture`). T&B log lines come from `src/store/tradersLog.ts` (same diff-based shape as the Seafarers lines). The T&B variants' block (`TradersVariantsBlock`: Strongest Ports holder + everyone's harbor VPs, the event deck, damaged roads, Friendly Robber reminder) shows in every game that has a variant on, Seafarers and base included. Barbarian Attack adds its own block (prisoners, knights, gold, conquered buildings per player; barbarians on the coast; deck; last expel) and ⚔ knights / ⛓ prisoners / 🏚 conquered badges (`BarbarianAttackBadges`).

## Traders & Barbarians

Self-contained module under `src/game/modules/traders/`. Scenarios live in `src/game/modules/traders/board/scenarios/`. Same modular layout machinery as Seafarers / Fun Maps; `swamp`, `lake`, `wateringHole`, and `castle` are new non-producing terrains (treated like desert for token skipping). The current builds ship **Rivers of Catan**, **Fishing on Catan**, **Merchant Trains**, **Barbarian Attack**, plus the **Friendly Robber**, **Strongest Ports** and **Catan Event Cards** variants (see "T&B variants" below — they work with any rule set) — the Traders & Barbarians combo scenario and the Catan for Two variant are deferred to follow-up commits.

- **Multi-number hexes** — `Hex.extraNumbers` (data field, absent on ordinary hexes) lets one hex carry several numbers; read numbers only through `hexNumbers` / `hexRollsOn` / `hexPips` in `src/game/board/hexNumbers.ts` (production, robber block, logStore's blocked count, AI pip math, `HexTile` → `MultiNumberToken`). Layout knobs in `scenarioTypes.ts`: `ScenarioPosition.zone` + `pools.zoneTerrains` (terrains forced into an area), `pools.printedNumbers` (a tile's own numbers), `pools.stackedTokens` (a set-aside disc stacked onto another number's hex). None draw RNG when unused, so other boards are unchanged.
- **Rivers of Catan** (2025 rulebook p. 11-12; map per TB-MAP-SPEC) — two fixed river tiles: (-1,-1) ore → (-1,0) brick → (-1,1) sheep → (-1,2) swamp, and (1,-1) ore → (1,0) brick → (1,1) swamp; 12 random hexes (wood 4, wheat 4, sheep 2, brick 1, ore 1); the 2 disc stacked on the 12 (`stackedTokens`); robber on the (1,1) swamp; T&B frame harbors. `state.rivers: RiverPath[]` (hexes source → mouth + mouth edge) and `state.riverEdges` = the 7 bridge sites (shared river edges + mouths), resolved in `board/resolveRiversAndFishing.ts`. Roads never go on bridge sites (setup too). `buildBridge`: 2 brick + 1 wood (`COSTS.bridge`), 3 per player (`MAX_BRIDGES`), joins own road / bridge / building, not past an opponent's building (`canPlaceBridge`), not via Road Building, counts for Longest Route, +3 gold. Gold: +1 per road on any edge and per settlement on any corner of the 7 river-tile hexes, setup included (`coins/gold.ts`: `vertexIsOnRiverTile` / `edgeIsOnRiverTile`). 10 VP.
- **Coins** (`src/game/modules/traders/coins/`) — `state.coinsInPlay` (scenario flag `coins`, set by createGame; Rivers now, Barbarian Attack / the T&B scenario should set it too). `player.gold` is public, not a card (no discard, theft or Monopoly). `spendGold { resource }`: 2 gold → 1 card, max 2 per turn (`state.goldSpendsThisTurn`, cleared on turn change by `withTradersTurnFlags`, which wraps every T&B handler). `buyGold { give }`: 1 gold for `getBankTradeRate` cards. Player trades may include gold (`giveGold` / `receiveGold` on propose / counter / `PendingTrade`, only with coins in play). Change gold only through `addGold(state, pid, delta)`, which refreshes the wealth tiles.
- **Wealthiest / Poor Catanian** — `state.wealthTiles` only when the scenario sets `wealthTiles` (Rivers). Wealthiest = unique max-gold player with ≥ 1 gold (+1 VP); Poor = everyone tied for the least gold, including the all-tied start (−2 VP each). `calculateWealthTilesVp` feeds `calculateVictoryPoints`.
- **T&B variants** (`src/game/modules/traders/variants/`) — each variant is its own small `RuleModule` (`tradersVariantModules(settings)`), switched on by `settings.tradersVariants` for ANY rule set (base, Seafarers, T&B scenarios; C&K too except Event Cards). `getActiveModules` puts them first. Hooks they use: `validators.moveRobber` + `validators.robberVictim`, `derive` (refreshed state after every action, before the win check), and `applyNextModuleHandler(state, action, moduleId)` (engine.ts) to wrap an action and hand it on to whichever module handles it next. `createGame` keeps the variants and bumps the VP target for Strongest Ports in every game; `supportsNeuralAi` is false with any variant.
- **Friendly Robber variant** — `variants/friendlyRobber.ts`. ANY building of a player with ≤ 2 public VPs rules a hex out (`friendlyRobberTargets`); with no valid hex only the desert(s) are legal (no desert: non-producing hexes, then any). Stealing from a ≤ 2 VP player is never allowed (`validators.robberVictim`). UI and AI read the shared engine helpers `robberHexAllowed(state, hex, mover)` and `robberStealCandidates(state, mover, hex)` (PlacementOverlay, RobberStealDialog, RobberOrPirateDialog, `src/ai/robber.ts`); the base `handleMoveRobber` uses `robberStealCandidates` too, so no `if (variant)` in the base robber code.
- **Strongest Ports variant** — `state.strongestPorts = { holder }`, refreshed by the variant module's `derive` hook (and the T&B build wrappers) via `recalcStrongestPorts`. Sticky like Longest Road (rulebook p. 4): the first player with ≥ 3 port-VPs (settlement on a harbor = 1, city = 2) takes it; a challenger needs strictly MORE than the holder; a holder below 3 loses it (to a unique 3+ leader, else nobody). +2 VP via `calculateStrongestPortsVp`; `createGame` bumps the VP target by 1.
- **Fishing on Catan** (2025 rulebook p. 9-10) — the lake goes on a random spot of the inner 7 (`zone: 'inner'` + `zoneTerrains`) with printed 2/3/11/12 (`printedNumbers`; `numberToken` 2 + `extraNumbers` [3, 11, 12]); all 18 discs on land; `state.lakeHexId`. `state.fishingGrounds: FishingGround[]` = 6 frame tiles `{ vertices[3], edges[2], token }` in the coastal notches, numbers 4/5/6/8/9/10 dealt with the seeded RNG. `maybeDistributeFish` (`fishing/production.ts`, called from the base dice handler): a producing ground pays every building on its 3 corners, the lake every building on its corners (robber on the lake blocks all four numbers), 1 token per settlement / 2 per city, drawn one at a time from the active player clockwise; the boot goes face up to `state.oldBootHolder`; the discard pile reshuffles when the supply is empty. Second starting settlement on a ground / the lake draws 1 token. 10 VP (11 with the boot, `hasPlayerWon`).
- **7-token cap** — a draw past 7 tokens (boot excluded) stops that player's drawing and queues them in the `'fishSwap'` phase (`state.fishSwap = { queue, returnTo }`, `getActingPlayerId` → queue head): `swapFish { token | null }` discards one token and draws a replacement, or keeps the hand (`fishing/swap.ts`). Swaps resolve after everyone's normal draws, in turn order.
- **Robber off-board state** — Fishing (and Merchant Trains) start with `state.robberActive = false`; the robber enters on any hex on a 7 or Knight (base `moveRobber`). The 2-fish spend takes it off again (rejected when it's already off).
- **Spend fish (`spendFish`)** — `effect.kind`: `removeRobber` (2), `steal { target }` (3, random card via seeded `rngState`), `takeFromBank { resource }` (4), `buildRoad { edge }` (5, normal road rules), `buyDevCard` (7, top card; a VP card counts at once). Tokens must be in hand and sum ≥ cost; excess is lost. `pickFishTokens` (least waste, then fewest tokens) is shared by `SpendFishDialog` and the AI. All five are in the UI; the free road uses UI mode `fishRoad` (PlacementOverlay).
- **Old boot (`passOldBoot`)** — held in `state.oldBootHolder`; pass on your turn to a player with ≥ your public VP (hidden VP cards excluded). The holder needs +1 VP to win.
- **createGame routing** — when `expansions.includes('traders')` and `tradersScenarioId` is set, route to `generateTradersBoard`. T&B plays 3-6 (`createGame` throws above the scenario's `maxPlayers`; no 7-8 boards) and is mutually exclusive with Seafarers and C&K; `createGame` throws for invalid combos.
- **T&B 5-6 (Phase 11; 2025 T&B 5-6 rulebook, maps in TB56-MAP-SPEC)** — each scenario declares `layout5_6p` plus `board5_6` (the board facts that differ: rivers, fishing grounds + tokens, watering holes, castles / expel order, `prepareLayout`); the generator reads `scenarioForPlayers(scenario, n)` = `{ ...scenario, ...board5_6 }` at 5+. Shared geometry in `board/scenarios/board5_6.ts` (`TB_DISCS_5_6` = the real CATAN 5-6 discs, two 2s and two 12s — the base game's `NUMBER_TOKENS_5_6` is left alone; `TB_OUTER_RING_5_6`, `isInner5_6`, `tbPositions5_6`); harbors `TB_FRAME_PORTS_5_6` (11 printed, pinned by `fiveSix.test.ts` via the hexes each touches, like every bridge site / fishing ground / train start). Rivers: three river tiles (the 5-6 one mountains → pasture → pasture, no swamp, mouth across (2,0)'s NE edge), 10 bridge sites, 28 discs with no 2-on-12 stacking, robber on the (-2,3) swamp. Fishing: two lakes on random inner hexes with their own printed numbers (`ScenarioPosition.printedNumbers`: 2/3/11/12 and 4/10), `state.lakeHexIds` (read lakes via `lakeHexes(state)`, `fishing/lakes.ts`), 8 fishing grounds (4,5,5,6,8,9,9,10), 44-token pool (`buildInitialFishPool(n)`). Merchant Trains: watering holes (-1,-1) and (0,1) (`state.wateringHoleHexIds`, read via `wateringHoles(state)`), six starts (`resolveAllWagonStarts`), 33 wagons. Barbarian Attack: castles (-3,0) / (2,0) (`ba.castleHexes`, read via `castleHexes(ba)`; castle edges = both), deserts (2,-1) / (-3,1), printed discs with two coastal 5s and 9s (`coastalHexesWithNumber`: a landing roll puts a barbarian on every coastal hex with that number, one `rolls` entry each), 48 barbarians, expel clockwise from the (-2,-1) 5. Paired turns need nothing scenario-specific: the T&B end-of-turn wrappers run for whichever seat `currentPlayerIndex` is, so Player 2 gets their own voting round (as acquirer) / knight step + expel, and per-turn coin spends reset at the P1 → P2 hand-off. `src/ai/traders/fiveSix.sim.test.ts` plays 5p / 6p all-AI games of every scenario and checks Player 2 uses each mechanic.
- **Merchant Trains** — `wateringHole` hex fixed at the centre (no desert); T&B frame harbors (`TB_FRAME_PORTS_3_4`); robber off the board; 12 VP. `merchantTrains/trains.ts` models trains explicitly: `state.wagonStarts` (the NW / NE / S corners of the watering hole, resolved geometrically by `resolveWagonStarts`; each with the start edge leading away and its far end), `state.merchantTrains: MerchantTrain[]` (`{ id, start, head, ended, mergedInto? }`) and `state.wagons: TradeWagon[]` (`{ edge, front, train }` — `front` is the intersection the wagon faces, so the art draws nose to tail). `legalWagonPlacements(state)` = free start edges (new train, `train: null`) + free land edges at every running train's head; a `WagonPlacement` is `{ edge, train }`. `applyWagonPlacement` draws from the 22-wagon supply and updates trains: a front reaching another running train's front merges (arriving train `ended`, `mergedInto` the other, which goes on from there); reaching any other wagon ends it; a front with no free edge ends. `canPlaceWagon(state, edge)` = some legal placement on that edge. Only `buildSettlement` / `buildCity` set `state.builtThisTurn` (roads / bridges don't). `handleEndTurnWithWagonVote` (`merchantTrains/turn.ts`): no building → normal end; no legal spot → normal end; exactly one spot → placed without a vote (`decidedBy: 'onlyOption'`); else `openWagonVote`.
- **Wagon voting** (`merchantTrains/voting.ts`) — `state.wagonVote = { acquirerId, order, stage: 'bid' | 'assign', turn, bids, assignments }`. `submitWagonVote { cards }` (wool / wheat only, may be empty = pass) goes round once from the active player clockwise; cards leave the hand at once (face up). Then: an absolute majority (> half of all votes) → `placeWagon` phase with that player (`pendingWagonPlacement.reason: 'majority'`); no votes → the active player (`'noVotes'`); else stage `assign`, where each bidder sends `assignWagonVotes { location }` → a unique top location is placed straight away, else the unique top bidder chooses (`'mostVotes'`), else the active player (`'activePlayer'`). `placeWagon { edge, train? }` by the placer. `placeAndFinish` places, returns every bid to the bank, records `state.lastWagonVote`, lets the acquirer win right there (end of turn is still their turn), then calls base `handleEndTurn`. `getActingPlayerId` returns the bidder / assigner / placer, so AIDriver and hot-seat handoffs follow the round.
- **Merchant Trains UI** — `WagonVoteDialog` (docked; public bids as pills, steppers + Pass / Bid for the seat whose turn it is, prompts for assign / placement), `WagonSpots` (BoardSVG: every legal placement as a lettered ghost wagon facing its train's way, for all seats; `placementTags` gives the same letters to dialog, board and log), PlacementOverlay click targets for the placer / assigner (two spots on one edge split it by half), `Wagon` art (grey wagon side-on, cab + drawbar at the front), `WateringHoleMarker` (ponds + hut art, green start arrows, red crosses on N / SE / SW), `MerchantTrainsBlock` in the Scenario tab (trains, supply, open spots, wagon VPs, current / last vote), log lines from `src/store/tradersLog.ts`.
- **Merchant Trains scoring** — `calculateLongestRoad` adds +1 to path length for each traversed edge that ALSO has a wagon on it (rulebook: a wagon on a road edge counts as an extra road). `calculateMerchantTrainsVp` (`scoring/merchantTrains.ts`) adds +1 VP per settlement / city whose vertex has ≥ 2 incident wagon edges. Both feed into the master `calculateVictoryPoints`.
- **Catan Event Cards variant** (`variants/eventCards/`) — `state.eventCards = { deck, current, newYear?, pending? }`. `deck.ts`: 36 numbered cards on the exact 2-dice odds (1×2 … 6×7 … 1×12; the rulebook doesn't print each card's number — ASSUMPTION documented there: Robber Attacks on the six 7s, 16 A Beautiful Day) plus New Year; `buildEventDeck(rng)` puts New Year 6th from the bottom (seeded `state.rngState`). Events needing answers open phase `eventResolution` with `pending.choices` (in turn order from the active player; `getActingPlayerId` = `choices[0].playerId`), answered by `resolveEvent { resource?, target?, edge? }`: takeResource (Plentiful Year, Calm Seas, Tournament), giveResource (Good Neighbors → left neighbour, handed over together; Helpful Neighbor → a poorer player), steal (Conflict: Largest Army holder or unique top knight player; Trade Advantage: Longest Route holder; `target: null` passes), damageRoad (Earthquake). Robber Flees → desert or off the board (`robberActive: false`). Epidemic → production with cities counted as settlements. Earthquake: `state.damagedRoads`; `canConnectRoad` refuses all roads of a player with a damaged road, `canPlaceSettlement` refuses either end of any damaged road; `repairRoad { edge }` costs `REPAIR_ROAD_COST` (1 brick + 1 wood). UI: `EventCardDisplay` replaces the dice (DiceDisplay), `EventChoiceDialog`, board road pick in PlacementOverlay, `DamagedRoadMarker`, ActionBar 📜 Flip / 🔧 Repair, Costs row, `TradersVariantsBlock` in the Scenario tab (any game). AI: `src/ai/traders/eventCards.ts` (`chooseEventAnswer`, `tryRepairRoad` before road building). Not combined with C&K yet (`createGame` throws).
- **Barbarian Attack** (2025 rulebook pp.15-19; all under `src/game/modules/traders/barbarianAttack/`) — fixed number discs (coastal 2-6 / 8-12 once each, so every non-7 roll names one coastal hex), castle `(-2,2)` and desert `(2,-2)` on the coast, terrain dealt separately for the coastal ring and the 7 inner hexes (`TradersScenario.prepareLayout`), T&B frame harbors. `state.barbarianAttack` = `{ barbarians: Record<HexId, 0-3>, supply, coastalHexes (expel order: clockwise from the 4 by the castle), castleHex, knights: Record<EdgeId, PlayerId>, prisoners, deck, discard, pendingCard?, movedKnights?, lastEvents? }` (36 barbarians = supply + coast + prisoners; 1 starts on the 2 and the 12). `coinsInPlay: true`, `noLargestArmy`, `robberActive: false`, empty `devCardDeck`, no wealth tiles. UI: `src/ui/game/traders/BarbarianAttack*.tsx` (board art incl. the castle tile pips and tipped conquered buildings, click overlay, ActionBar bars, badges, Scenario-tab block); log lines from `src/store/barbarianAttackLog.ts` (events in `lastEvents`).

For Barbarian Attack (`src/ai/traders/barbarianAttack.ts`) one scoring function, `positionValue` (fights our knights would win at the next expel, barbarians threatening our buildings, our conquered buildings), drives knight placement, the end-of-turn knight moves (one improving move at a time, wheat only when it pays, castle knights always moved), Capture and Treason; `tryBuyBarbarianCard` buys the scenario's cards before roads (not when about to afford a city), `barbarianAttackNeedsRoads` lets it road out once nothing is left to upgrade, and the 7 steal reuses `chooseStealResourceTarget`. `barbarianAttack.sim.test.ts` runs all-AI 3p / 4p games to the end.

## Multiplayer model

- **Trystero over Nostr relays** (`@trystero-p2p/nostr` ≥ 0.26, all in `src/net/room.ts`) for WebRTC signaling: WebSockets on port 443 to public Nostr relays, so it works on cellular and most locked-down networks. No backend. App ID `catan-friends-v1`; room code doubles as the password for E2E encryption. Every device derives the same 8 relays from the app ID (`RELAY_REDUNDANCY`; changing it or `APP_ID` splits old and new builds onto different relays). STUN only, no TURN: two devices both behind strict (symmetric) NAT can find each other but not connect.
  - **Must stay on Trystero ≥ 0.26.** 0.20 reconnected a dropped relay socket without re-sending the room subscription, so a phone whose page had been in the background (host sharing the code from another app) could announce itself but never hear anyone again: the guest found nobody and the host never saw them. Its relay list had also gone stale. 0.26 resubscribes, caps reconnect backoff at 60 s, and pauses / resumes on offline / online.
  - **Background pages**: `room.ts` pauses relay reconnection while the page is hidden (letting it through every 30 s, so desktop background tabs stay reachable) and reconnects immediately when the page is visible again.
  - **Joining** (`networkStore.joinRoom`): the guest sits in `connecting` (a dedicated "Looking for room ABCD…" card, never an empty lobby) until the host's `lobby` / `start` / `snap` arrives. After `JOIN_TIMEOUT_MS` (25 s) it gives up with `joinFailure` = `{ code, reason, relays, peersSeen, waitedMs }`: `noRelays` (this device reached no relay: its network), `noHost` (other devices on the code, none hosting), or `notFound` (relays fine, nobody answered: wrong code, or the host's page is asleep). The error card shows the reason plus a debug line and Try again (`retryJoin`). Codes are trimmed / upper-cased; the input disables autocorrect.
  - **Network test** (Play online → Network test, `src/ui/newGame/NetworkTest.tsx` + `src/net/diagnostics.ts`): per device, relays reached and the route type from an ICE probe (`open` / `strict` = symmetric NAT / `local` = no public route); plus a pair test where two devices on the same test code see each other with live ping. Use it on both devices of a pairing that won't connect.
  - **Tests**: `src/net/fakeRoom.ts` is an in-memory `room.ts` (one hub on `globalThis`); `src/store/networkStore.test.ts` runs several "devices" (fresh store copies via `vi.resetModules`) through it: join, not-found / no-host / no-relay failures, retry, game start, move sync, rejoin, spectating. `diagnostics.test.ts` covers candidate parsing and route classification.
- Trystero `peerId` is volatile (Math.random). Stable identity is a `localStorage` UUID (`catan.uuid`), exchanged via the `hello` channel.
  - **Local testing escape hatch:** appending `?fresh` to the URL switches identity storage to `sessionStorage` so two windows in the same incognito session (which share `localStorage`) don't collide on the same UUID.
- Full state replication: every peer holds the full `GameState`.
- Actions (not state diffs) are broadcast as `{ action, byUuid }` envelopes; receivers verify the UUID owns the action's player seat.
- Randomness (dice, dev card draws) is decided by the acting player and included in the action payload, so all peers reduce to the same state.
- **Lobby** is host-authoritative: host owns `LobbyState`, broadcasts it on changes. Host clicks Start → broadcasts the initial `GameState` via `start`. Min seats = 3 (Catan official rules); engine still tolerates 2 for tests.
- **Rejoin / spectator**: when a peer joins mid-game, the host responds with `snap` (gameState + chat + seatUuids). Newcomer's role: UUID matches a seat → guest; otherwise spectator (read-only).
- **Disconnect**: pause indefinitely. UI shows offline dot + `ConnectionStatusOverlay`. Multiple peers can map to one UUID (testing); we only emit "disconnected" once the last peer for that UUID leaves.
- **AI in online**: only the host runs `AIDriver` (`role === 'host' || role === 'solo'`). If host drops, AIs freeze.
- **Chat**: in-memory in `networkStore.chat`, not part of `GameState`. System messages auto-generated on joins/leaves/game-start.
- No anti-cheat — friends-only.

## Trading model

- Bank/port trades (4:1 / 3:1 / 2:1) via `bankTrade { give, receive, count? }`. `count` defaults to 1; the engine validates `rate * count` available and `count` available in the bank, so a 3× port trade is one action.
- Player-to-player: open broadcast. `proposeTrade` creates a single `pendingTrade` slot in state; any opponent with the receive-side resources can `acceptTrade` (first acceptor wins). The proposer can `cancelTrade`. Non-proposers can `rejectTrade` (visible on the banner) or `counterTrade` (replaces the pending trade, swapping perspectives). The active turn player may also `cancelTrade` to walk away from a counter. Engine auto-cancels on `endTurn`.
- AI evaluates pending trades via `shouldAcceptTrade` (threshold ~0). If it wouldn't accept, `tryCounterTrade` searches edit-distance-1 tweaks for a counter both sides would tolerate. Otherwise it `rejectTrade`s.
- `AI_PROPOSER_WAIT_MS` (10 s) and a 2.2 s stagger between AI evaluators give the human time to react to an AI offer.
- `tradesProposedThisTurn` bounds AI to 2 proposals per turn (humans unlimited). Counters don't count against the cap.

## AI model

- Pure heuristic, stateless across turns. Defined in `src/ai/`.
- `chooseAction(state, playerId)` returns the next action or null (meaning "end turn"). The React `AIDriver` component schedules this with ~450 ms delays for visibility, and ~10 s for the AI's own pending trades so humans can react.
- Priority tree: city > settlement > devCard > road > favorable player trade (2:1) > bank trade > generic player trade > endTurn. Favorable player trade fires before bank to prefer mutually-good 2:1 swaps over throwing cards to the bank.
- **Win plans (`src/ai/winPaths.ts`)**: six encoded 10-VP templates (cityArmy, cityRoad, cityBothBonuses, sprawlRoad, sprawlBoth, maxBuild). `chooseWinPlan` scores each by `estResourceCost + productionMismatch` and returns the cheapest reachable plan; the rest of the AI consults `gap.newSettlementsNeeded` etc. to pick thresholds.
- **Threat model (`src/ai/threats.ts`)**: `assessThreats(state)` flags each opponent as `closeToWin` (within 2 VP), `closeToLargestArmy` (knights ≥ max(currentLA, 2)), `closeToLongestRoad` (road length ≥ 4), and records the resources that advance their next VP step (`dangerousResources`). Consumed by trade scoring (refuse swaps that hand a threat the win), robber placement, and steal-target selection.
- **Trade hygiene**: `tradeResourcesThisTurn` on `GameState` logs which resources each player has given/received via completed trades this turn. The AI uses it to skip reverse trades (don't give what you just received) and roundabout trades (don't receive then immediately re-give). Cleared on real turn advance.
- **Dev-card gate**: AI skips a dev card if it could instead settle now, finish a settle with one more resource, or unlock a settle spot with one road. Dev cards are slow VP; expansion compounds.
- **Road gate**: builds only when (a) no reachable open settle spot AND target endpoint scores `≥ ROAD_TARGET_THRESHOLD` (default 4.5, dropped to 3.5 when the active win plan needs more settlements), or (b) pursuing Longest Road (within 2 of claim length — threshold drops to 1.5). Contested-endpoint penalty (-2 per enemy road touching the target vertex) keeps the AI from racing into spots opponents can settle first.
- **Bank trade aggression**: bank-trades only when (1) we have a concrete build goal AND a specific shortfall, or (2) hand size ≥ 8 (next 7 would force a discard). The give-side picks a resource we have spare (above goal needs); receive-side prefers shortfall on the active goal.
- Resource weights: ore/wheat 1.3, brick/wood 1.1, sheep 0.9. Tunable in `src/ai/value.ts`. Gold weighted 1.6 (above any single resource — reflects the choice-of-resource on production) plus a flat +1 per gold hex bonus in `vertexScore` (smooths bad-luck spells).
- Port valuation: 2:1 of a resource we produce here = 3.5, of a resource we produce elsewhere = 2.5, of one we don't produce = 1.2; generic 3:1 = 1.5.
- **Island bonus**: `vertexScore` adds `islandBonusAt(state, player, vertex) * 3` (the bonus this player would still earn there).
- **Ship building** (`src/ai/seafarers/ships.ts`): Seafarers step between settlement and road. `tryBuildShip` scores an edge by a short look-ahead (`navValue`: the best settlement spot or scenario target within 5 ship-steps, minus 1.1 per step) so the AI crosses open sea; scenario bonuses come from `shipEdgeBonus` / `scenarioTargetValue` in `src/ai/seafarers/scenarios.ts` (tribe pickups, villages, Pirate Islands line steps via `shipAdvancesLine`; it holds the final step to its fortress until it has 4 warships). `tryMoveShip` re-routes one open-ended ship when the gain is ≥ 3. `reportNeeds` has a `'ship'` goal when no settlement spot is open and a worthwhile ship exists. Setup may pick a ship instead of the road.
- **Scenario-aware vertex scoring** (`src/ai/value.ts`): `vertexScore` skips unrevealed fog terrain (no peeking), adds a fog bonus, a Cloth bonus for vertices near untraded villages, and a Pirate Islands penalty for hexes on the fleet loop.
- **Pirate Islands**: Knights are played whenever a ship can become a warship; `stealResource` robs the biggest hand. **Cloth**: the pirate steals cloth when it completes a pair. **Forgotten Tribe**: `chooseTribePortEdge` puts a 2:1 port by the building producing that resource.
- **Wonders of Catan** (`src/ai/seafarers/wonders.ts`): claims the best wonder it qualifies for (cost vs. its production), then builds levels when affordable; a winning level runs in the early instant-win pass.
- One competent difficulty level. No state in the AI; no memory between turns (per-turn trade history lives on `GameState`, not the AI). The base game also offers Easy / Normal / Hard trained networks instead (see "Learned agent"); the heuristic still plays every other rule set and covers any move a network can't make.

## Learned agent (`src/ai/nn/`)

Neural-network AI for the **base game only** (`supportsNeuralAi(settings)`: no expansions, standard board, no T&B variants), modeled on card-collecting's SSP / Sushi Go pipeline. Expansions and Fun Maps keep the heuristic. Trained by `training/` (see below), shipped as three frozen difficulty levels. Same purity contract as the rest of `src/ai/`.
- **AI levels** — `settings.aiLevel?: 'easy' | 'normal' | 'hard'` (`AiLevel` in `src/game/types.ts`). Picked on the New Game screen and, online, by the host in the lobby (`LobbyState.aiLevel`, `hostSetAiLevel`; default `normal`); only shown when the game has an AI seat and `supportsNeuralAi`. Unset (or a non-base game) = the heuristic. `neuralLevel(state)` in `index.ts` is the one check. Levels are checkpoints of run `training/runs/catan/main`, scored as one seat vs three heuristics at 4p (25% = heuristic strength): easy = update 100 (29.5%), normal = update 1,000 (61%), hard = update 10,000 (83.5%; 75 / 65 / 59% at 3 / 6 / 8p).
- `levels.ts` + `policies/` — one policy JSON per level (~2.6 MB, `?url` import so it ships as a hashed asset, not in the JS bundle), fetched once per page by `loadAiLevel(level)`; `loadedAiLevel` reads it synchronously. Tests and tools install nets read from disk with `setAiLevelNet`. To re-freeze a level, copy `training/runs/catan/<run>/policies/update_NNNNNN.json` into `policies/` and point `AI_LEVELS` at it.
- `runtime.ts` — `CatanPolicyNet`: the graph net's forward pass in plain TypeScript (no ML deps), reading a `catan/gnn@1` file exported by `training/catan/model.py`. It refuses files whose encoder / action-space versions or dims don't match this build. `greedyPolicy(net)` plays the top legal slot. `test_training.py::test_typescript_runtime_matches_pytorch` pins it to PyTorch — keep the two in step when the architecture changes.
- `session.ts` — `KnowledgeSession.sync(initial, actions, live, seats)` folds logStore's log into every AI seat's knowledge, incrementally; it replays from the start when the log shrinks (undo) or the game / seats change, and returns null (→ heuristic) when the log began mid-game (rejoin snapshot) or replay doesn't reproduce the live state.
- **AIDriver wiring** — `src/ui/game/AIDriver.tsx` holds AI seats until the level's file loads (a failed fetch falls back to the heuristic), then tries `chooseNeuralAction` for every AI move and trade answer, falling back to `chooseAction` / the heuristic trade logic when the network has nothing to decide (e.g. waiting on its own offer, which the heuristic cancels) or can't run. Networks never counter-offer.
- `knowledge.ts` — per-seat card counter folded forward one action at a time (`observeTransition(k, before, action, after)`, or `knowledgeFromHistory(initial, actions, viewerId)` from logStore's log). Keeps weighted joint hypotheses over every hand: a steal the viewer didn't take part in branches by what the victim could have lost; later public changes prune (a spend, a trade offer showing what the offerer holds, a monopoly revealing exact counts). Also records rolls, dev buys, and face-up dev plays. Must start at game creation. `MAX_HYPOTHESES` 2048 (peaks seen: ~200 at 4p, ~1300 at 8p); `repairs` must stay 0.
- `observation.ts` — `observe(state, viewerId, knowledge, { draft })` is the ONLY place the pipeline reads `GameState`. It reads opponents' resources only as hand-size totals and opponents' dev cards only as counts; it never reads deck order or RNG. Seats by offset in turn order (0 = viewer). `decision` is what the viewer must answer now; multi-part answers (discard one card at a time, robber hex then victim, Road Building edges) carry a `CatanDraft`. `observation.test.ts` scrambles every hidden field and asserts the observation and features don't change — keep it passing.
- `board.ts` — canonical hex / vertex / edge order (geometric) plus topology index arrays, cached per board shape. Sizes: 19/54/72 at 3–4p, 30/80/109 at 5–6p, 37/96/132 at 7–8p.
- `encode.ts` — encoder v1: per-hex (29), per-vertex (38), per-edge (11) feature rows plus a 371-float global vector. Board pieces carry an owner seat slot (me / next1–3 / far). Placement bits re-derive the base rules; `encode.test.ts` checks them against the engine's predicates. **Bump `ENCODER_VERSION` on any layout change** (the dims are pinned in tests).
- `reward.ts` — terminal reward = win + placement + VP share, centred on the table mean (4p, 10/8/6/4 VP → +1.15 / −0.12 / −0.38 / −0.65). Step-capped matches take −0.5 per seat. `vpPotential` gives optional potential-based shaping.
- `actions.ts` — action space v1: board-relative slots `[vertices][edges][hexes][119 globals]` (264 at 4p) so a graph net's per-entity logits line up with them. `legalMask(obs)`, `decodeSlot(obs, slot)` → reducer action or the next `CatanDraft`. Player trades are a fixed menu of 1:1 / 2:1 / 1:2 offers (≤ 2 a turn, never repeated in a turn, only when some opponent could hold the ask); no counter-offers. `actions.test.ts` is a two-way oracle against the reducer. **Bump `ACTION_SPACE_VERSION` on any slot change.**
- `agent.ts` — `actWithPolicy(state, id, knowledge, policy)` runs a slot policy through the draft loop to one reducer action.
- `testSupport.ts` — seeded heuristic-vs-heuristic games with every seat's knowledge tracked, plus `scrambleHidden`. Caution: the heuristic AI can stall forever (every settlement upgraded, no road worth building), so sims and training envs need a step cap.
- **Changing the encoder or action space** (bumping `ENCODER_VERSION` / `ACTION_SPACE_VERSION`) invalidates every shipped policy: the runtime rejects them and `levels.test.ts` fails. Retrain and re-freeze all three levels in the same change.

## UI conventions

- **Layout**: GameView is a CSS grid — board (top-left), bottom strip (bottom-left, holds `HandPanel` + `ActionBar`), side panel (right, full height, holds `SidePanelTabs` + `OpponentPanel` + `BankPanel`). The right pane's shape is intentionally stable across turns so attention stays on the board.
- **Compact screens (phones, small tablets, short landscape windows)** — `GameView.css`: `@media (max-width: 900px), (orientation: landscape) and (max-height: 500px) and (max-width: 1100px)`. The game is exactly one screen tall (`height: 100dvh; overflow: hidden`) and **must never scroll as a page**: the map claims every touch drag (`touch-action: none` on `.board-pan-wrap`), so anything below the fold becomes unreachable. This was the old bug: in landscape (768–900 px wide hit the stacked tablet layout) the page was 1,200+ px tall with the panels off-screen, and in portrait with browser bars the End turn button was clipped. Portrait: board on top, hand + actions strip below (≤ 50dvh, scrolls inside itself). Landscape: board left, hand + actions in a right column. The side panel (`.gameview-side`: players with VP, log / chat, bank) is a drawer, opened by the labeled **Players** button at the board's bottom-left (`.gameview-players-btn`) and closed by its Close button or the scrim; the player list is ordered first. The same landscape clause is repeated in `HandPanel.css` and `ActionBar.css` (stacked hand / buttons). Don't add page-level scrolling on compact screens; to check a change, load a mid-game state at 390×664, 360×560, 844×390 and 932×430 and confirm `document.scrollingElement.scrollHeight === innerHeight`.
- **Board rendering**: `BoardSVG` is a pure presentational component that takes `game: GameState` as a prop (plus an optional `overlay`). Live play uses `Board.tsx` (a thin wrapper that reads from the store and adds `<PlacementOverlay />`); the end-game replay reuses `BoardSVG` directly with a reconstructed historical state. Sub-components (`HexTile`, `Settlement`, `City`, `Road`, `Ship`, `PortMarker`, `Robber`, `PirateMarker`) take their `BoardState` via prop rather than via `useGameStore`, so they're agnostic to whether they're rendering live or historical state.
- **HandPanel viewing rule**: always shows the device-bound human's hand, not the acting player's. In solo this is the last-acknowledged handoff player (falling back to the first non-AI seat); in online it's the local seat. AI hands are never shown — opponents' info lives in `OpponentPanel`. All-AI games are an exception: with no human seat, HandPanel shows the *acting* AI's hand (so spectators can follow).
- **OpponentPanel ordering**: iterates `game.playerOrder`, not `game.players`. Seat-join order is meaningless during play; turn order is what matters at-a-glance.
- **Active turn indicator**: there is no PhaseBanner. Whose turn it is is conveyed by (a) the highlighted row in `OpponentPanel` (`.opp-acting`) when an opponent is acting, and (b) the presence of action buttons in `ActionBar` at the bottom when it's your turn.
- **ActionBar extras**: shows a `↶ Undo` button (solo/hot-seat, only when `lastActionSnapshot` is set), a `Costs` button that opens the `CostCheatsheet` popover, and hover tooltips on each build button with the resource cost. For 5+ players the paired-player rule applies: when the acting seat is Player 2 (third seat to Player 1's left), the trade button collapses to a 🏦 Bank trade entry — player-to-player trades are gated off at the engine level.
- **Hover ghost (build mode)**: `PlacementOverlay` lifts hover state for vertices / edges. The hovered ghost layers a faint full-shape silhouette (`SETTLEMENT_PATH_D` / `CITY_PATH_D` / road line) in the acting player's color underneath the dashed validity outline.
- **Docked dialogs (`DialogShell variant="docked"`)** are the default for action prompts (trade, discard, year-of-plenty, monopoly, robber steal). They render in overlay containers inside the board:
  - **Trade overlay (`.gameview-trade-overlay`)** at top-center of the board holds `PendingTradeBanner`, `PlayerTradeDialog`, and `BankTradeDialog`.
  - **Dialog overlay (`.gameview-dialog-overlay`)** at bottom-center of the board (just above the bottom strip) holds the other one-off dialogs.
  - Each container neutralizes the `.dialog-dock` absolute positioning so its child renders in place.
- Use `variant="modal"` for screens that should block (GameOver, rulebook overlay).
- **Player colors** come from `src/ui/shared/playerColors.ts` — `PLAYER_COLORS`, `PLAYER_COLOR_HEX`, `playerColorVar(c)`. Don't duplicate the `PLAYER_COLOR_CSS` map inline; reuse the helper. There are 10 colors; the new-game seat editor (`NewGame.tsx`) lets each seat pick one independently. Conflict resolution: if seat X picks the color seat Y already has, seat Y swaps to X's old color so all seats remain unique without any disable-locking dance.
- **Clocks**: `GameClock` (top of the board, runs from game start) shows total wall-clock time; `TurnTimer` shows the active player's countdown when `settings.turnTimerSec > 0`. When the per-turn timer hits zero the UI auto-finishes any committed sub-phase (discard / robber move / etc.) using AI defaults, then dispatches `endTurn`. AI seats ignore the timer — they pace themselves via `AIDriver` (~450 ms per micro-step; ~10 s on the AI's own pending trade so a human can respond).
- **Game log**: `LogPanel` reads from `logStore.entries`. Steal entries deliberately omit the stolen resource (private info). Trade offers, rejections, cancellations, and per-roll resource gains are NOT logged — only completed trades and the roll itself. Revolution-based turn markers (`── Turn N ──`) tick over when the table cycles back to the first player in `playerOrder`. For 5+p paired turns the P1→P2 hand-off doesn't increment the counter; only the P2→next-P1 transition does. Auto-scroll only fires when the user is already at the bottom (`wasAtBottomRef`); chat has the same behavior.
- **Match graph**: `MatchGraph` reads `logStore.timeline` (per-step `vp`, `handTotal`, `gainedTotal`, `gainedByResource`, `knightsPlayed`, `longestRoadLength`, `tradesCount`, `tradesGiven`/`tradesReceived`, plus `turnNumber`) and `logStore.stats` (roll counts, resourcesInCirculation). Tabbed line charts (VP, resources earned, hand, knights, longest road, trades count, trade efficiency, by-player, by-resource) plus two game-wide bar charts (dice frequency, circulation). X-axis is labeled in turn numbers (thinned to ~10 labels); hover snaps to the nearest timeline step and shows an x-unified crosshair + tooltip including `Turn N · step M`. Embedded in `GameOverDialog`, which also offers a `Replay` tab.
- **Replay**: `Replay.tsx` plays the finished game forward. It steps through a filtered list of *board-changing* actions (builds, ships, robber/pirate moves, dev-card plays) while reconstructing `replayState` from the full action list, so resources/VPs stay correct even though rolls / trades / end-turns aren't stops on the slider.

## Training (`training/`, offline, never shipped)

PPO from scratch against the real engine, mirroring card-collecting's `training/ssp/`. Node processes (`training/catan/vec-env.ts` behind `env-server.ts`, bundled by `npm run train:build`) run the matches, heuristic seats and encoding; Python (`train.py`, `model.py`) runs every network seat on the GPU. Batch replies over stdio are a JSON line plus raw feature bytes. Training starts by imitating the heuristic (the env labels each learner decision with the heuristic's slot via `training/catan/teacher.ts`; teacher-forced, then DAgger), then PPO with a fading pull toward the heuristic. Worker kinds: self-play (4 learner seats), vs three heuristic AIs, mixed tables (learner + heuristic + 2 past checkpoints), vs three past checkpoints. A guard moves self-play workers to heuristic tables when an eval vs the heuristic drops clearly below the best. Offers everyone rejects cost a tiny penalty. Workers alternate in two groups so env time and GPU time overlap. The network is a graph net (hex / vertex / edge messages + a global vector, ~0.5M params, bf16 trunk); its policy files (`catan/gnn@1`) carry every tensor and both versions. Evals run in background processes every 100 updates (vs heuristic, vs 500 updates earlier, vs a `--fixed-opponent` checkpoint, 4-way tables) → `progress.md`. `--opponent-play greedy` makes frozen opponent seats play their top move instead of sampling. Rough speed on the dev box (10-core Xeon w5-2445 + RTX A2000): ~4.9 s per update of ~14k decisions.

## Non-goals (do not implement)

- Persistent game saves between sessions
- User accounts, matchmaking, lobby browser
- Anti-cheat / verifiable randomness
- Monetization, ads, telemetry
- Server-side anything

## Conventions

- Strict TypeScript. No `any` unless genuinely necessary.
- Co-locate tests next to the code: `engine.ts` and `engine.test.ts` side by side.
- The game logic layer must not import from `src/ui`, `src/net`, or `src/store`.
- The net layer may import from `src/game` but not `src/ui`.
- Path alias: `@/` → `src/`.
- `createGame` shuffles `playerOrder` with the seeded RNG by default so signup order doesn't confer a first-player advantage. Tests that depend on `p0` starting pass `randomizeTurnOrder: false`.

## Token distribution rule

Every layout's number tokens are **symmetric around 7**: `count(N) == count(14-N)`. This mirrors dice symmetry (P(2) = P(12), P(3) = P(11), etc.). For odd-total layouts where strict symmetry is impossible, the smallest possible asymmetry (1) is placed on the rarest pair (2/12 or 3/11) so the most-common 6/8 stay balanced.
